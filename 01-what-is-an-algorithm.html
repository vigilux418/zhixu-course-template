算法，是把问题想清楚

桌上摊着八张卡片，每张写着一个数字。找出最大的那张，你大概几秒钟就能做到——可你能把这件事说得让任何人都照做、且结果一致吗？这一讲，我们就从这个动作开始，把“找最大值”变成一段可以检查的算法。

  • 说清输入、处理与输出
  • 把直觉拆成可执行的步骤
  • 读懂第一段 Python 算法
  • 用循环不变式解释它为什么对

先从一个日常动作开始

假设桌上有八张卡片，数字依次是 8、3、12、5、9、2、16、7。你多半会先看第一张，把它记在心里；接着看第二张，比记住的数大就换掉它；一直看到最后一张，答案自然浮出来。

这个过程里，你其实做了三件事：确认手里有什么、规定每一步怎么做、说清最后交付什么。日常的许多事情都是这个结构：在书架上找一本书、在词典里查一个词、按价格从低到高挑商品。算法（algorithm）algorithm 一词源自 9 世纪波斯数学家花拉子米（al-Khwarizmi）名字的拉丁文译名 Algoritmi。他把印度—阿拉伯数字的运算方法系统化；后来这个词逐渐泛指一切明确的求解步骤。不过是用更严格的语言，把这类过程完整地描述一遍。

把一个问题，变成一系列清晰、能看到终点的步骤——这是理解算法的起点，也是动手写程序之前该有的准备。

算法的价值不在于“看起来聪明”，而在于“谁来做都一样”：同样的输入、照着同样的步骤，就一定得到同样的结果。这正是它能交给计算机执行，也能交给别人复核的原因。

输入、处理、输出

先别急着写代码。用三句话把这件事说清楚，一个算法就有了骨架。

  1. 确定输入

    问题交给我什么？这里是一组数字，也就是八张卡片上的八个整数。输入决定了起点，也暗示了需要处理哪些情况。

  2. 规定处理

    从第一个数开始，把它记作“当前最大”；之后每读一个数，就和“当前最大”比一次，更大就替换记录。

  3. 交付输出

    所有数字都看过后，把记录下来的那个数交出去。按上面的规则，它一定是这组数里最大的。

这里的三个词会反复出现：输入（input）、处理（process）、输出（output）。很多流程图，本质上只是把这三件事画了出来。一个问题，三段思考：

  1. 输入八张写着数字的卡片
  2. 处理逐张比较，更新记录
  3. 输出这组数里的最大值

算法做的事，就是把已知的信息，变成想要的答案。

把步骤写成程序

把上面三步翻译成 Python，只要十来行。每一行都能对应回一个具体动作：记住、比较、更新、交出答案。代码下方的三条讲解，对应最值得记住的三行；没学过 Python 也没关系，先读讲解即可。

def find_max(numbers):
    if not numbers:
        raise ValueError("输入不能为空")

    largest = numbers[0]
    for number in numbers[1:]:  # 逐个看剩下的数
        if number > largest:
            largest = number
    return largest

print(find_max([8, 3, 12, 5, 9, 2, 16, 7]))  # 16
  1. 先记住第一张：它是“已经看过”的数里最大的。
  2. 只有更大的数，才值得更新记录。
  3. 返回记录；遍历结束时，“已经看过”就是“全部”。

标亮的第 2–3 行不是“找最大值”本身，而是给算法划定的适用范围；真正的主体从第 5 行开始。

把这段代码存成 find_max.py，再运行 python find_max.py，屏幕上会打印出 16。

为什么第 2–3 行不是多余的检查？

如果跳过空列表判断，numbers[0] 会抛出 IndexError：报错说的是“下标越界”，而不是真正的原因“输入为空”。换一种写法（比如先把记录设成 0）甚至不会报错，只是安静地返回一个错误答案，等它被带到很远的地方才暴露。

提前失败，是把边界条件写进接口约定：调用者明确知道空输入不被接受，而不是等错误自己浮出来。

算法与程序不是一回事。算法是“步骤的思路”，可以用中文、流程图或代码表达；程序只是其中一种表达，还得符合某门语言的语法。同一种算法，可以写成不同语言、不同风格的许多程序。

让过程在眼前发生

算法必须亲眼见过才可信；弄懂一个算法的最好办法，就是动手试一试。

高德纳《计算机程序设计艺术》卷 1

点“下一步”，亲手把这套步骤走一遍。高亮的是正在查看的卡片，标着“最大”的是当前的记录，变暗的卡片已经比过，不可能再是答案。

留意两件事。第一，最大值并不会每张都换，中间有几次只是看过就走。第二，没看过的卡片仍然可能更大：16 在第 6 次比较时就记下了，可要等看完最后一张 7，才能确定它就是答案。所以不能因为连续几次没更新就提前收工。

为什么这个算法一定不会漏掉最大值？在循环的每一刻，都可以说出一句始终成立的话：“当前记录的，是我已经看过的所有数字中最大的。”开始时只看过第一张，这句话显然成立；每看一张，要么它不更大、记录不动，要么它更大、记录换成它，这句话依然成立。看完所有卡片时，“已经看过”就等于“全部”，记录自然就是全局最大值。

这种在过程中一直成立的性质，叫作循环不变式（loop invariant）。它比“试过几个例子都对了”更有说服力：它覆盖的是一类输入，而不是碰巧试过的那几个。

在继续之前，用这张清单快速自查。

  • 看过找最大值的逐步演示，知道记录会在什么时候改变
  • 在纸上重走一遍，写下每次比较后当前的最大值
  • 用自己的话说清：为什么中途停下会漏掉答案

边界，是算法的另一半

一组数字总有最大值吗？如果输入是空的——一张卡片也没有——“最大的那个”就不存在。这时算法应当明确地说“无法回答”，而不是随便返回一个数字让人误会不同语言与库的约定并不统一：Python 的 max([]) 抛出异常，JavaScript 的 Math.max() 返回负无穷，SQL 的 MAX 对空表返回 NULL。选哪一种，取决于调用方更希望“立刻失败”，还是“继续处理”。。那段代码的第 2–3 行，就是把这种情况挡在门外。

边界条件不能靠“调用者应该不会传空”来维持。输入为空时，函数要么明确抛错，要么按约定返回一个可解释的结果；把规则写进接口，才算真正定义了算法。

再看另一种容易忽略的情形：若最大的数出现两次，比如 16 和 16，结果仍然是 16，没有问题；但若问题改成“最大的数在第几张卡片”，两个 16 就会给出两个不同的正确答案。可见问题的提法，决定了算法需要记住什么、返回什么。写代码之前把这句话想清楚，比事后补检查省力得多。

把问题改成“最大的数在第几张卡片”，算法要记住的就不再是数值，而是位置：

def find_max_position(numbers):
    if not numbers:
        raise ValueError("输入不能为空")

    position = 0
    for i in range(1, len(numbers)):
        if numbers[i] > numbers[position]:
            position = i
    return position + 1  # 第几张：从 1 开始数

四张卡片依次是 4、16、9、16，调用 find_max_position([4, 16, 9, 16]) 会返回几？如果把第 7 行的 > 换成 >= 呢？

解答

返回 2。第二个 16 并不比第一个“更大”，记录停在最先出现的那一张。换成 >= 之后，相等也会更新记录，返回 4，也就是最后出现的那一张。

两个答案都说得通，区别只在题目有没有讲清楚：并列时要第一张，还是最后一张。

还有一个小细节值得留意：输入里允许出现小数或负数吗？8、3、12 都是正整数，但算法本身并不依赖这一点，换成 −5 或 3.5 依然成立。真正依赖的只有一条：这些数两两之间能比大小。

检查你的理解

先凭直觉选一个答案，再看解析。判断自己是否真的理解，标准是能不能说出“为什么”。

按照这一讲的算法，8 张卡片一共要做几次大小比较？

  1. 8 次，每张卡片都比一次
  2. 7 次，第一张用来设定起点
  3. 不确定，取决于最大值排在第几张

回到演示数一数：第一张卡片有没有和谁比较？

第一张用来设定记录，不算比较；剩下的 7 张各与当前最大值比较一次，因此 8 张卡片需要 7 次比较。一般地，n 张卡片需要 n - 1 次。

照同样的做法，100 张卡片需要比较多少次？

第一张设定起点，其余 99 张各比较一次：100 - 1 = 99。

用自己的话解释：为什么“试了几组数据都对”还不足以说明算法正确？循环不变式补上了什么？

试过的例子只覆盖有限的几种输入。循环不变式给出的是一句对任何输入都成立的话——“当前记录的，是已经看过的数里最大的”——它从第一轮一直保持到最后一轮，所以结论对所有输入成立。

本讲小结

  • 算法是一套明确、有限、能到达终点的步骤，骨架是输入、处理与输出。
  • 同一种算法可以用中文、流程图或程序表达；程序只是其中一种写法。
  • 空输入、重复最大值这类边界情况，应当在步骤里就交代清楚。
  • 循环不变式让我们证明算法对所有输入成立，而不只是对试过的例子成立。
